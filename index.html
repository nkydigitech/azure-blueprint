LEVEL 0

Azure Fundamentals

Start with simple language, then connect each idea to the technical model.

Cloud computing

Simple: Rent computing resources over the internet instead of buying and operating all the hardware yourself.

Technical: On-demand compute, storage, networking and managed services delivered through provider APIs and control planes.

Azure

Simple: Microsoft's cloud platform.

Technical: A global set of cloud services exposed through the Azure Portal, APIs, CLI, SDKs and infrastructure-management systems.

Resource Group

Simple: A logical folder for related resources.

Technical: A management boundary used to organize resources, apply tags, permissions and lifecycle operations.

Subscription

Simple: The Azure account boundary you use to organize and pay for resources.

Technical: A billing and management container associated with a Microsoft Entra tenant.

Region & Availability Zone

Simple: A region is a geographic Azure location; zones are separate physical locations within supported regions.

Technical: Regions provide geographic placement; availability zones provide datacenter-level fault isolation for supported services.

Tenant

Simple: The organization's identity directory.

Technical: A Microsoft Entra ID directory containing identities, groups, applications and identity policies.

Management plane

Operations that create and manage resources, commonly through ARM, Portal, CLI, PowerShell, Bicep or Terraform.

Data plane

Operations against the resource itself, such as reading a blob, querying a database or serving application traffic.

Shared responsibility

Azure secures the underlying cloud infrastructure; you remain responsible for your configuration, identities, data and workloads according to the service model.

LEVEL 6

Identity & Security

Authentication vs Authorization

Authentication: proves who you are. Authorization: determines what you can do.

Example: Entra ID can authenticate a user; Azure RBAC can authorize that identity to read a resource group.

RBAC vs Entra roles

Azure RBAC controls access to Azure resources. Microsoft Entra roles control directory and identity-management operations. They solve different authorization scopes.

Managed identity

Let an Azure resource obtain an identity without embedding long-lived credentials in application code.

Key Vault

Centralize secrets, keys and certificates with controlled access. Avoid hard-coding credentials in repositories or workflows.

LEVEL 9

Don't Get a Surprise Azure Bill

Cost control is part of cloud engineering, not an optional final step.

Know what can cost money

VM compute, managed disks, public IPs, databases, networking, storage, managed Kubernetes and other services can generate charges depending on configuration and usage.

Use guardrails

Use budgets, alerts, tags, Cost Management and the Pricing Calculator. Verify current free-tier terms before relying on them.

Clean up

After each lab, identify all dependent resources and delete what you no longer need. Stopping one resource does not necessarily stop every associated charge.

TROUBLESHOOTING

Problem → Diagnosis → Fix

az: command not found / not recognized

Confirm Azure CLI is installed, restart the terminal, and run az --version. If the command is still unavailable, check that the Azure CLI installation directory is on PATH.

Subscription not found

Run az account list --output table. If the expected subscription is missing, confirm you logged into the correct tenant/account and have access to the subscription.

Permission denied

Separate authentication from authorization. Confirm the signed-in identity and the Azure RBAC role/scope required by the operation. Avoid granting Owner when a narrower role is sufficient.

SSH to VM fails

Check the VM is running, the public IP/DNS is correct, the NSG allows the intended SSH source, the username/key is correct, and no local network control is blocking the connection.

Port 80 is unavailable

Check the NSG, the web server process, the VM's local firewall and the public IP path. Test locally on the VM before debugging the external path.

GitHub Actions deployment fails

Inspect the workflow logs, validate Azure authentication and permissions, confirm the target resource exists, and verify environment variables. Never solve a secret failure by committing credentials.

Quota/region error

Read the exact deployment error, check service availability and quotas for the subscription/region, then select an allowed region or request quota where appropriate.

Resource deletion fails

Inspect dependencies and locks. Some resources have child resources or protection settings that must be removed first. Re-run a resource inventory before retrying.

CAREER ROADMAP

Where do you go from here?

Certifications can validate knowledge, but projects, troubleshooting ability and evidence of hands-on work matter too.

Azure Administrator

Focus: subscriptions, identity, networking, compute, storage, governance and operations.

Cloud / DevOps Engineer

Focus: Git, CI/CD, IaC, containers, observability, security and automation.

Cloud Security Engineer

Focus: identity, RBAC, Defender, network controls, secrets, policies and threat detection.

Cloud Architect

Focus: architecture decisions, reliability, security, cost, governance and trade-offs.

SRE / Platform Engineer

Focus: reliability, automation, developer platforms, Kubernetes, observability and operational excellence.

Azure Developer

Focus: application development, APIs, serverless, managed databases, containers and deployment.

Certification note: Use current Microsoft Learn pages to verify the latest certification names, exam objectives and retirement/transition announcements before planning an exam.
